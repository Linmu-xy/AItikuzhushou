# 能力导向开放命题 V2 重构契约

用户要求：重构知识库命题，不以资料段落限定模型能力；按需联网；以真实考核价值为目标。

## 边界

- 知识库定义主题、学习阶段和可用素材，不是答案白名单。稳定学科知识、迁移场景、明示模拟数据均可用；真实图纸数字、现行标准和时效事实必须核验。
- 新建计划使用 OPEN_ASSESSMENT_V2；旧 V1 / 职业路径、数据库结构、人工审核和导出接口保持兼容。不重写既有题目。
- 新计划不强迫每题绑定文档；只有依赖原图的题位必须有真实文档和页码。长资料归纳覆盖全库，不截取前半部。
- 命题、独立作答、审查均可请求公开主题搜索；OFF 不联网。每题和整次运行设有界预算、缓存和失败记录。搜索失败不等于通过，不应导致无关题位整批失败。
- 独立作答输入不得含作者答案、解析、评分标准、命题意图、私有参考答案。随后审查正确性、条件充分性、能力对齐、干扰项、评分可操作性及重复性；不凭字数、词汇重合或绝对词机械判错。
- 审题拒绝时最多定向重写一次并重新独立作答；服务不可用保留原题待审，不重新付费命题。恢复任务跳过已经完成的题位。
- 保留实际调用 usage 日志与内部研究/独立解答轨迹；不向考生展示内部调研数据。AI 判断不能替代正式试测或专家定标。

## 验证

实测扩展：并发规划与审题触发额度服务的 Java monitor / 数据库行锁交叉等待。额度 reserve/complete/event 改为独立短事务，避免继承网络规划长事务；增加真实 Spring 事务并发回归。这是完成新链路并发可用性的必要共享层修复。

1. 单测：跨学科、无来源题、长资料、真实图、按需搜索/关闭/预算/失败/隐私、盲解、评分与答案分歧、有限修复与断点恢复、旧计划。
2. 后端全测试和打包；涉及 UI 设置时前端构建。
3. 先分析历史 CAD 样本，再创建小规模独立测试项目进行真实链路回归；提前说明 API 消耗，不自动审核或覆盖用户项目。

采用 rewrite-plan 的分步与所有权契约；该技能的 code/index.json、token-map、DESIGN.md 是视觉重构输入，本次后端任务不适用。单独存放本计划以保留已有 plan/ 文件。

设计参考：ETS evidence-centered design（能力主张、可观察证据、任务）；CMU assessment alignment（考核方式与学习目标一致）。不强制所有题包装职业情境，也不将基础知识题一概视为无效。
