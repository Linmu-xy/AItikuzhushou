# 命题流水线 V3

题库生成现在按“证据蓝图 → 批量写题 → 紧凑职业审查 → 失败题修复”运行。Pro 模式默认每批 3 个题位，设计和写题分别只调用一次模型。

## 模型输出边界

用户最终看到并保存的命题字段只有：

- `stem`
- `options`
- `answer`
- `analysis`
- `scoringRubric`

蓝图中的岗位任务、决策点、条件、标准依据和干扰项机制仅作为内部设计卡保存。审查阶段只保存分数、失败码和短反馈；通过的选择题使用 `optionChecks`，失败题才输出详细 `optionReviews`。

## 质量门禁

每题必须能追溯到职业标准证据，并满足岗位对象、任务、必要条件和唯一决策点。选择题还要满足四项同一决策维度、错误项具有真实专业误判、没有明显文字线索。

独立审查器返回 `discriminationScore` 和 `outsiderSolvableScore`。默认要求前者不低于 75，后者不高于 35；任一阻断标记都会触发定向修复。

## Token 和耗时观测

DeepSeek 响应中的 `prompt_tokens`、`completion_tokens`、`reasoning_tokens` 会写入 `model_usage_daily`，每次调用的模型、思考强度、字符数、真实 Token 和耗时写入 `model_usage_events`。

当前账户可通过 `GET /api/model-quota/breakdown` 查看当天按模型和思考强度聚合的消耗，定位最贵的阶段和配置。

## 重试策略

单批生成失败的题位才会单独重试。完整修复默认最多一次，选项层问题优先走选项修复。任何不通过质量门禁的候选都不会作为低质量兜底交付。

审核器超时、空响应或返回非法 JSON 会标记为 `REVIEW_SERVICE_ERROR`，最多只重试审核本身一次。候选题保存在对应题位并标记 `REVIEW_PENDING`，不会因为审核服务故障重新生成题目。用户点击失败任务的“继续补题”时，系统先执行审核专用重试；审核恢复后通过的题目直接入库，确实不合格的题目才进入正常修复流程。
